Покрываются ли все возможные инструкции opentype.js?


Да — для обычных контурных глифов твой рендерер покрывает всё, что opentype.js кладёт в Path.commands: 
в документации перечислены только M, L, C, Q, Z.

И для outline-based шрифтовых путей ты уже закрыл нужный набор:
M — новый контур, L — прямая, Q — квадратичная кривая, C — кубическая кривая, Z — замыкание контура. 
В текущем API opentype.js нет отдельных команд вроде H, V, S, T, A на уровне Path 
— по крайней мере, в публичной документации они не перечислены.

Но есть важная оговорка: не любой вывод opentype.js — это просто один набор контуров. 
В Glyph.getPath() есть отдельные ветки для drawSVG и drawLayers, то есть цветные слои COLR/CPAL и SVG-картинки 
могут возвращаться как layers/image-слой, а не как обычный commands-path.

Если нужно “железно любой glyph, который умеет opentype.js”, тогда нужен ещё fallback для drawLayers и drawSVG.

Пропуск M и Z в рендеринге сanvas:

Команды OpenType/Canvas M (moveTo) и Z (closePath) — это структурные команды:
M задаёт начало контура // Z закрывает контур (линия в точку старта)

Если твой формат currentContours уже хранит:
contour[0].anchor — первую точку для moveTo
contour[n].closed === true — флаг, означает closePath()

… это уже воссоздании логики M и Z, и повторять их не нужно.
ctx.moveTo(first.x, first.y);   // это ваш M
if (closed) ctx.closePath();    // это ваш Z

Поэтому пропускать оригинальные M и Z — нормально.

Когда это может быть проблемой:
Если какой-то contour может быть пустым
Тогда contour[0] будет undefined.
→ Добавь страховку:
if (!contour.length) return;
